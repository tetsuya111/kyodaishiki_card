# ai-chat-shell 要件定義の修正（対話時の RAG 検索の明示、埋め込みモデル設定）

- 日時: 2026-09-16 22:40
- 種別: spec

## 何をしたか

`.kiro/specs/ai-chat-shell/requirements.md` を以下の観点で修正した。

- **対話時も RAG 検索を行うことを明示**: 背景・ゴール・ストーリー2（対話）・ストーリー5（RAG を用いた対話）に、ユーザー発話のたびにベクトル DB を検索し関連カードをプロンプトに含めることを受け入れ基準として追加。明示的な検索コマンド（ストーリー4）とは独立に自動で行うことを記載。成功指標に「対話時の RAG 検索実施率」を追加。
- **通常の対話も可能だが基本はカード中心**: カードと無関係な話題も拒否しないが、その場合も RAG 検索を実行し「該当カードなし」をプロンプトに含めること、システムプロンプトで「基本はカードの検索とカードの情報をもとにした対話」であることを指示することを記載。
- **埋め込みモデルの設定（既定 Voyage AI）**: ストーリー1 に埋め込みプロバイダ・モデルの指定、既定 Voyage AI（公式 Python SDK）、`VOYAGE_API_KEY` 未設定時の扱い、現在の設定確認コマンドを追加。ストーリー3（RAG 登録）に使用モデル名の記録、モデル不一致時の警告、進捗表示を追加。Non-Goals・非機能要件（プライバシー: 登録時は全カードが埋め込みプロバイダへ送信される）・依存関係（`voyageai`、ベクトル DB）・制約・未解決事項・用語集を更新。

併せて、`myutil` を import しているファイルの記載誤り（`shells/__site__.py` → 実際は `shells/bookmeter.py`）を `docs/requirements.md` と `.kiro/specs/automated-testing/requirements.md` で修正した（`requirements-txt` スペック側はユーザーが修正済み）。

## なぜ

- メモの「対話の際にも RAG からカードを検索しプロンプトに含める」「基本はカードの検索・カード情報をもとにした対話」「登録時の LLM も設定可能、既定 Voyage AI」という意図が、初版では暗黙的または未記載だったため。
- 埋め込みモデルが確定したことで、未解決事項だった「RAG の検索方式（ベクトルか語彙か）」はベクトル DB 方式に決まり、残る論点（既定モデル、ベクトル DB ライブラリ、ハイブリッド検索の要否）に差し替えた。
